# 困难群众补贴受理服务

面向街道民政专干的补贴受理服务。工作人员打开一笔申请，即可看到**资格依据、具体缺件、下一位办理人**，无需在多部门回执之间来回比对。

## 运行

```bash
npm start           # 显示 CLI 帮助
node src/index.js demo          # 端到端演示（受理→补正→核验→发放→重启恢复→脱敏→隔离）
node src/index.js view A-1001 --role staff --district 新河街道 --store data/demo-events.jsonl
node src/index.js queue --role staff --district 新河街道
npm test            # node:test 单元测试（14 个用例）
```

项目仅使用 Node.js 内置模块，无第三方依赖；`fixtures/` 与演示数据均为脱敏样例。

## 数据入口（fixtures/）

| 文件 | 作用 |
| --- | --- |
| `policies.json` | 政策样例：低保 / 残疾人两项补贴 / 临时救助的生效日、所需材料、资格标准、**优先级与排他分组（可配置）**、办理流程 |
| `field-dictionary.json` | 字段字典：敏感字段各角色脱敏档位、材料有效期口径（收入证明开具当月有效，跨月即失效） |
| `conflicts.json` | 冲突材料：重复申报、同人多户、证明跨月失效等冲突规则（reject/review/warn/supplement 四种处置）与样例 |
| `context.json` | 原始现场资料（F-021 家庭两笔重复申报记录） |

## 架构

事件溯源：所有业务动作先追加到 JSONL 事件日志（`data/*.jsonl`，append + fsync），再更新内存投影；重启后重放日志恢复同一状态。

```
src/
  config.js              加载 fixtures，政策/排他分组/冲突规则查询
  store/event-store.js   只追加事件日志（启动时截断崩溃残留的半行）
  domain/
    time.js              +08:00 日历、政策周期、证明有效期计算
    projection.js        事件 → 状态投影（成员/材料连续版本、回执索引、支付索引）
    evaluation.js        资格评估：缺件清单、政策标准、重复/冲突检测
    masking.js           按角色脱敏（策略来自字段字典）
    service.js           受理服务：受理、补正、核验回执、核准、发放、视图
  demo.js                端到端演示
  index.js               CLI 入口
```

## 关键业务保证

- **同一政策周期内一个有效家庭申请**：同一家庭在同一排他分组、周期重叠的在办申请只留一笔；重复申报登记冲突并驳回，高优先级新申请可替代低优先级在办件（优先关系由 `policies.json` 的 `priority` 与 `exclusivityGroups` 决定，调整配置即改变低保/残疾/临时救助的优先关系）。
- **连续版本**：家庭成员与材料补交都形成连续版本（旧版本保留、新版本按生效日接替），资格判断按评估日的有效版本进行；收入证明开具当月有效，跨月自动点名失效并给出补交指引。
- **补正不断链**：补正轮次、每轮缺件、补交记录全部留痕，重启后完整恢复；材料齐后自动关闭轮次并回到街道审核。
- **回执乱序/重复安全**：核验与发放回执按 `receiptId` 幂等，重复投递只生效一次；回执先于申请到达时挂起、受理后自动挂接；支付回执先于支付单到达时在支付单建立时回挂；无对应支付单的迟到回执只留痕并挂冲突，**绝不二次发放**。
- **不重复发放**：支付键 = 家庭 + 项目 + 政策周期，重复发起返回同一支付单；重启后支付索引仍在。
- **驳回原因不遗漏**：驳回原因逐条追加、按来源去重，永不覆盖；替代、核验驳回、人工驳回均完整留痕。
- **街道隔离**：非审计角色只能访问本街道申请与待办队列，跨街道访问直接拒绝。
- **按角色脱敏**：身份证号、手机号、银行账号、地址按字段字典中各角色档位脱敏（如 finance 仅见银行账号后四位、auditor 身份证仅首尾各一位），申请人角色可见本人全量信息。

## 打开一笔申请能看到什么

`getApplicationView` 返回：资格依据（命中政策、每项材料核验状态、每条资格标准的实际值与结论）、具体缺件（缺哪份、为何失效、如何补）、下一位办理人（环节 + 角色 + 待办事项）、驳回原因、补正轮次、冲突、支付记录与完整历史轨迹。
